# ADR-0015: v0.2.0 Consolidated Release Architecture

Status: Accepted · Date: 2026-08-27

## Context

v0.2.0 must deliver 14 epics (A–N) as **one consolidated release** on the existing TypeScript/Node.js single-package stack (ADR-0001/0002), on branch `master`, without splitting into v0.3.0/v0.4.0. The repo is at `0.1.1` on master (HEAD `595f468`), with a controlled tag-triggered release workflow (`.github/workflows/release.yml`, tags `v*.*.*`, OIDC Trusted Publishing). The next release must remain offline-first, deterministic, and safe-by-default while adding readiness scoring, provider profiles, rule packs, dashboard, diagnostics, SDK, and a VS Code extension without destabilizing the existing product path.

## Decision

1. **Single consolidated release**: All v0.2.0 implementation tasks target the same `0.2.0` package version and the same `v0.2.0` tag/release. Internal phases/epics are scheduling constructs; no artifact carries a different minor version. Execution order is defined in `docs/v0.2.0/EXECUTION_PLAN.md` (requirements → shared contracts/SDK boundaries → score+graph+profiles+rules → optimize → action/watch/diagnostics/benchmarks → dashboard → VS Code → security hardening → docs → integration matrix → release readiness). No circular dependencies.

2. **Reuse + extend**: Existing ADR-0001 (toolchain Node ≥22, CI 22+24, pnpm+Biome+Vitest), ADR-0003 (offline-first), ADR-0005 (fs boundary), ADR-0006 (instruction graph), ADR-0007 (exit codes 0–5), ADR-0008 (MCP SDK), ADR-0012 (pack/cache) remain unchanged and are reused. Extensions are ADR-0016..0024 below; any intentional behavioral change requires a version-bumped schema, recorded fixture re-baseline, and entry in `CHANGELOG.md`.

3. **No architectural replace without justification**: The instruction graph (`src/core/instructions/graph.ts`), filesystem engine, scan pipeline, pack engine, policy engine, and task system stay as the working foundation (ADRs 0005/0006/0011/0012). Strengthening is additive (v2 schemas, new pure functions) rather than a rewrite.

4. **Multi-artifact envelope**: The npm package `@cynrath/agent-context-kit@0.2.0` remains the primary distribution; the VS Code extension (`extensions/vscode/*.vsix`) and the GitHub Action (`action.yml`) are version-aligned companion artifacts (same `0.2.0` string, independent audit rows in TRACEABILITY). See ADR-0023.

5. **Scheduling invariants**: Wave numbers increase strictly along dependency chains; parallelizable tasks are documented as `parallelizable: yes` only when they touch disjoint file sets (e.g., profiles vs graph vs rule packs). The next coding-agent prompt must execute tasks in dependency order without asking what to do next.

## Consequences

- Implementation tasks can be developed in parallel where the execution plan allows, but the final integration task (TASK-0024) blocks until every predecessor is complete and every gate in `docs/v0.2.0/DEFINITION_OF_DONE.md` passes.
- Any proposal that would require a database, cloud control plane, remote LLM, vector DB, telemetry backend, or arbitrary plugin execution is out-of-scope (REQ-V020-GOV-OUT-001) and must be rejected without an ADR.
- Master branch protection remains: normal `master` pushes never publish; only an annotated `v0.2.0` tag triggers `release.yml`. See ADR-0013/0023 and `CHANGELOG.md` policy.
