# ADR-0025: Browser Companion Architecture — Local Bridge + MV3 Extension Boundary

Status: Accepted · Date: 2026-08-29
Scope: ACKit Browser Companion v0.3

## Context

ACKit is offline-first and deterministic (`REQ-GOV-001/002`). Browser Companion must bring repository intelligence (task, instructions, context, evidence, readiness) into ChatGPT/Claude/Gemini/GitHub without giving a webpage direct filesystem access, shell execution, or silent upload. The extension is a **new consumer** comparable to CLI/MCP/Action/VS Code: it consumes the existing public SDK (`src/index.ts`) via a loopback bridge, not via direct disk or `chrome.scripting` injection of repository data.

Prior art audited 2026-08-29:
- `src/core/dashboard/server.ts` already implements a localhost HTTP server with `assertBindableHost`, security headers (`Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Cache-Control: no-store`), pagination, and redaction. It is the reference for localhost binding and header policy.
- `src/core/reporting/serve.ts` defines `NonLocalBindRefusedError` and loopback-only binding.
- `src/index.ts` public SDK is frozen (ADR-0021) and is the only supported import surface for consumers; internal `src/core/**` must not be imported by the extension.
- VS Code extension precedent (`extensions/vscode/`) proves `extensions/<name>/` as the repo convention for secondary build artifacts (own `package.json` → `.vsix`, not a pnpm workspace).

Constraints derived from the product prompt:
- No `<all_urls>`, no arbitrary path API, no `POST /write-file|run-command|git|execute`, no auto-submit, no automatic cloud egress, no aggressive DOM detach as default, three-layer fail-safe (Emergency Disconnect + per-site Safe Mode + CLI kill-switch + circuit breaker).

## Decision

### 1. Topology

```
Repository
   │
   ▼
ACKit Core / Public SDK (src/index.ts)
   │   scanRepository / buildContextPack / buildInstructionGraph / scoreRepository / TaskStore / validateSkills
   ▼
ACKit Local Browser Bridge  —  Node http.Server, binds 127.0.0.1 only (default), port 0 or --port
   │   GET /v1/status, /v1/repository, /v1/task/active, /v1/instructions/effective, /v1/context, /v1/readiness, /v1/evidence
   │   GET /v1/health (liveness), POST /v1/stop (revoke, loopback-only + token)
   │   Auth: Bearer <random 32B session token> generated at start, kept in memory, printed once to terminal, stored nowhere on disk
   │
   ▼
MV3 Browser Extension  —  extensions/browser/
   │   service worker (chrome.storage.session for token, chrome.storage.local for per-site prefs)
   │   Side Panel  (primary UI: connect/disconnect, health, attach/preview/insert, restore project context, performance controls)
   │   content scripts (site adapters, Shadow DOM where UI injected, noEval)
   │   site adapters: extensions/browser/src/adapters/{chatgpt,claude,gemini,github}/ (isolated contracts)
```

### 2. Package location and build

- Extension lives at `extensions/browser/` — mirrors `extensions/vscode/` convention. It is **not** a pnpm workspace package (single-package invariant ADR-0002 preserved). It has its own `manifest.json`, `src/` (TypeScript), built with `esbuild` to `dist/` and packaged with `web-ext`/`chrome` tooling; `pnpm-workspace.yaml` is NOT modified.
- Root `package.json` gains scripts `build:browser`, `lint:browser`, `typecheck:browser`, `test:browser` that delegate into `extensions/browser/` without polluting root lint scope (root `biome.json` excludes `extensions/browser/dist`).
- Icons: real PNGs at 16/48/128 generated by script (or omitted until generated) — never reference non-existent files (chrome-extensions skill mandatory rule #1).

### 3. Bridge is a new ACKit command, reusing existing seams

- New CLI: `ackit browser start|stop|status` (alias `ackit bridge` → same handler). Implemented as `src/cli/commands/browser.ts` + `src/core/browser-bridge/server.ts` (new) + `src/core/browser-bridge/token.ts`.
- Reuse: `resolveRepositoryRoot`, `TaskStore`, `buildInstructionGraph`, `resolveEffectiveStack`, `buildContextPack`, `scoreRepository`, `validateSkills`, `executeConfiguredScan` — same engines as dashboard, but trust boundary is distinct (Browser Bridge has its own token, host validation, CORS, rate-limit).
- Default bind `127.0.0.1`, port discovery via `listen(0)`. `0.0.0.0` refused unless `--allow-nonlocal` + explicit audit note (never default). `::1` treated as loopback.
- API is **read-only** in v0.3 (`GET` only except `POST /v1/stop`). No `POST /write-file`, `POST /run-command`, `POST /git`, `POST /execute` — any such proposal requires a new ADR and explicit user authorization.

### 4. Security boundary (summarized; normative in ADR-0026)

- Auth: `Authorization: Bearer <token>` required on every `/v1/*`. Token is `crypto.randomBytes(32).toString('base64url')`, held in `chrome.storage.session` (cleared on Emergency Disconnect and browser close) and in bridge memory only. No token in URL, no token in `chrome.storage.local` (persistent), no disk write.
- Host validation: strict `Host` header must be `127.0.0.1:<port>` or `localhost:<port>` or `[::1]:<port>` exactly; any other host → 403. DNS rebinding defense: server validates `host` header, not `origin` alone.
- Origin/extension identity validation: `Origin` must be `chrome-extension://<expected-id>` when the extension makes the request. During development the id is stable via manifest `key` derivation; in production the bridge accepts a registration handshake (`GET /v1/status` with token establishes session) and then pins the `Origin` to that extension id for the session lifetime. No wildcard CORS.
- CORS/CSRF: `Access-Control-Allow-Origin` echoes the pinned extension origin only; `Access-Control-Allow-Methods: GET, POST`; `Access-Control-Allow-Headers: Authorization, Content-Type`; `Access-Control-Max-Age: 600`. No `*`. Preflight requires token as well.
- Payloads: response JSON capped at 512KB (pack truncated via SDK budget), `Content-Length` guard, rate-limit 60 req/min per token (token bucket, in-memory), 10 req burst.
- Redaction: every bridge response runs the same 5-shape secret redaction (`ACKIT001-005`) and absolute-path scrub (`<local-path>`) as dashboard/bundle. Only repo-relative paths are emitted.
- Token lifecycle: short/controlled lifetime (default 12h, `--ttl` override), revocation on `POST /v1/stop`, on Emergency Disconnect (`chrome.runtime.sendMessage` → bridge abort), and on server close. After revoke, bridge refuses all requests until restarted.

### 5. Extension boundary

- Extension MUST NOT: read `file://` or arbitrary `http` repositories, accept filesystem paths from the webpage, execute shell/git, auto-submit, silently upload, expose generic localhost API to arbitrary origins.
- Permissions minimal: `storage`, `sidePanel`, `alarms` (+ `activeTab` only if needed for action click — otherwise host_permissions only). Host permissions scoped to `https://chat.openai.com/*`, `https://chatgpt.com/*`, `https://claude.ai/*`, `https://gemini.google.com/*`, `https://github.com/*`, `http://127.0.0.1/*` (loopback). Prefer `optional_host_permissions` for the four providers if the CWS review team requests it — the set stays narrow either way.
- Service worker is ephemeral: no in-variable state; all session data in `chrome.storage.session`/`local`. Use `chrome.alarms` for health polling, not `setInterval`.
- Side Panel is primary UI; `chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true })` (correct spelling) and `chrome.sidePanel.open({ windowId })` on `action.onClicked` — no `default_popup` alongside `setPanelBehavior`.

### 6. Emergency Disconnect / Safe Mode / Circuit Breaker (release-blocking)

- Side Panel always shows **Emergency Disconnect** (no confirmation): abort in-flight `fetch` via `AbortController`, clear `chrome.storage.session` token, stop `MutationObserver`/alarms/listeners, call `adapter.disconnect()` / `restore()`, remove injected classes/placeholders/UI, mark `disabledSites[hostname]=true` in `chrome.storage.local`, require manual Reconnect.
- Per-site Safe Mode: `Disable ACKit on this site` / `Restore page` / `Reconnect` per host. State is per-site so ChatGPT broken does not disable Claude.
- CLI kill switch: `ackit browser stop` → `POST /v1/stop` with token, or local proc kill if bridge is parented; revokes token, closes listener, refuses new requests until restart.
- Circuit breaker: adapter keeps `errorCount` sliding window (N=5 within 30s or 3 repeated `mutation-loop` detections) → auto Safe Mode for that host only, `observers stopped`, `page restored`, warning banner shown. Fail-closed: unknown DOM → no-op.

### 7. Conversation Performance Engine (safe default = Balanced)

- Goal: reduce browser render/DOM pressure, not model context window.
- Hierarchy: 1) `content-visibility` / `contain` (browser-native), 2) reversible CSS/class collapse, 3) code/media compact, 4) experimental detach only as separate opt-in, benchmarked, reversible.
- Controls: Compact older messages, Restore all, Show previous N, Pin/Keep visible, code-block collapse, media collapse, Conversation Navigator, visible/compacted counts.
- Safety invariants (from Tampermonkey PoC but re-derived): never touch React internals, preserve provider native virtualization, pause mutations while streaming (`stream start → pause; stream end → debounce → health check → compact eligible`), no auto-compact while user is reading older messages (near-bottom / scroll-distance check), preserve scroll anchoring, never compact focused turn, narrow `MutationObserver` (`childList:true, subtree:false` on closest conversation wrapper, debounced, incremental index), `chrome.storage.local` for settings (not website localStorage), every compact reversible via Restore/Emergency Disconnect, full cleanup on SPA route change (`location` / history pushState watcher, idempotent init).

### 8. Adapters

- Shared contract `Adapter { id, detect():boolean, healthCheck():{ok,reason?}, findComposer():Element|null, insertText(t:string):boolean, isStreaming():boolean, enumerateTurns():Turn[], compact(opts):CompactResult, restore():void, navigator():NavItem[], disconnect():void }` (types under `extensions/browser/src/adapters/types.ts`).
- Isolation: `src/adapters/chatgpt/` etc. each own their selectors; no core module knows provider selectors. Selectors are hints re-verified with DevTools MCP at implementation time (e.g., ChatGPT `#thread`, `[data-turn-id-container]`, `section[data-testid^="conversation-turn-"]` are not assumed permanent; health check fails closed to Safe Mode).

### 9. Alternatives considered

- Extension reading `~/.ackit` directly: rejected — violates bridge trust boundary, exposes FS to compromised page context.
- `0.0.0.0` bridge: rejected — widens to LAN; 127.0.0.1 + token is sufficient.
- `<all_urls>`: rejected — CWS will reject single-purpose violation; scoped host_permissions are correct.
- Aggressive DOM detach as default: rejected — risks React remount bugs; Balanced reversible mode is correct for stable.

## Consequences

- New modules: `src/core/browser-bridge/*`, `src/cli/commands/browser.ts`, `extensions/browser/{manifest.json,src/**,icons/**,sidepanel/**}`.
- New task graph: TASK-0044..0052 own the phases; this ADR is the architecture sign-off for TASK-0044.
- New tests: bridge protocol (Host/Origin/CORS/token/payload/rate-limit/redaction), adapter contract, Safe Mode, circuit breaker, reversible compact, MCP verification as pending evidence when MCP unavailable in agent.
